# 更新・点検の手順

## 再作図と情報更新の違い

`./build.sh`は、保存された記述と座標から地図を描き直します。ニュース、AIS、運賃、港湾情報などを検索する機能はありません。収録時の基準日は**2026年9月29日**です。

現在の地図として再公開するときは、情報を再確認して地図を編集します。実行日だけを新しい基準日として表示しないでください。基準日を据え置いて再利用する場合は、その時点の整理図であることが伝わるようにしてください。

## 情勢・内容を更新する場合

1. 各地図の出典Markdownを読み、変更の必要がある事項を選びます。紅海・ホルムズの通航、パイプラインの稼働、積替え地点、パナマの制限、費用に関する記述は特に時間に依存します。
2. 運営者、当局、業界機関等の一次資料と信頼できる報道を確認します。記事の公表日、出来事の日付、観測期間を分けて記録してください。匿名情報による報道と公式確認も区別します。
3. `maps/middle-east/build.py`または`maps/global/build.py`で、必要な線・ラベル・注記を編集します。座標は緯度経度の順序を確認し、既存の表現・変換処理に合わせます。
4. 確認した内容に合わせて、同じフォルダーの`metadata.json`の`as_of`を更新します。表題やクレジットを変える場合も同ファイルを編集します。基準日には`YYYY-MM-DD`形式を使います。
5. `docs/middle-east-sources.md`、`docs/middle-east-geometry.md`、`docs/global-sources-and-costs.md`など、対応する根拠と留保を更新します。
6. 対象の地図を再作図し、PNGを目視確認します。異常があれば元のスクリプトを直して再実行します。

地図上の説明は短く保ち、根拠や詳細な留保はMarkdownに記載します。ただし、単独で画像が共有されても重大な誤解につながらない程度の注記は残してください。

## 維持する表現

- **中東図：** NGLラインとその凡例は載せません。紅海・ペルシャ湾などの海域ラベルは水平に保ちます。湾内シャトルの起点はラス・タヌラ付近の代表位置で、個別便の実績として扱いません。バブ・エル・マンデブ海峡等の引出線を文字に重ねないようにします。
- **全球図：** 長い模式航路は滑らかな曲線とし、矢印をその曲線上の接線方向に置きます。引出線は直線、注記枠は長方形、影なしです。航路の鮮やかな元の配色を維持します。本文は36 pxの行送りを基本とし、末行下の余白を過大にしません。注記は必要な内容に絞り、「東京大学大学院 渡邉英徳研究室」の作図クレジットを維持します。
- **共通：** OSM系のダーク背景、読みやすい日本語、簡潔な注記を維持します。地図の描画線は模式表現であり、個船の航跡や航海上の推奨経路ではありません。

上記は保存版の意匠方針です。利用者から新たな指定があった場合は、その指示に合わせて更新してください。

## 出力の確認

```sh
./build.sh middle-east
./build.sh global
```

`dist/`のPNGを開き、縮小表示と等倍表示の両方で確認します。

- ラベル、注記、引出線、矢印が重なっていないか。
- 航路の曲線が意図せず陸地を横切ったり、海峡・港を飛び越えたりしていないか。
- 全球図の左右端をまたぐ航路が、滑らかに連続しているか。
- 引出線の端が対象航路や地点を指し、不要な矢印頭が付いていないか。
- 注記枠の中で、タイトル・状態・本文の行間と上下余白が自然か。
- 図の基準日、表題、凡例、作図クレジット、背景の帰属表示が適切か。
- 出典Markdownと図の表現が一致しているか。

`*.qa.json`は描画確認の補助です。自動検査だけでは、曲線と海岸の関係や記述の正確性までは判断できません。`--svg-only`ではPNGも描画確認用JSONも更新しないため、公開前は通常のビルドを行ってください。

## 背景を更新する場合

```sh
npm run refresh-basemap -- middle-east
npm run refresh-basemap -- global
./build.sh all
```

この処理だけはネット接続が必要です。背景と投影設定は組み合わせて使用します。画像だけを別サイズ・別範囲の地図に差し替えると、航路と海岸線がずれる原因になります。背景を変更した場合は、両者の整合と帰属表示を確認してください。

背景取得に失敗した場合は、既存背景で通常の再作図ができるか確認します。新しい背景が必要なときだけ、通信環境や配信サービスを確認して再取得します。

## 環境を変える場合

- 初期準備は`npm ci`を使い、保存された依存関係を再現します。
- Google Chromeがなければ、`npx playwright install chromium`の後に`CHROME_CHANNEL=chromium`を指定します。
- ChromeまたはChromiumの実行ファイルを選ぶ場合は`CHROME_PATH`、Pythonを選ぶ場合は`PYTHON`を指定します。
- 日本語が四角になる場合や文字幅が変わる場合は、日本語フォントを確認します。フォントやブラウザーの違いで、改行・字幅・描画が変化する可能性があります。
- Node.jsやブラウザーが使えない環境では、`./build.sh all --svg-only`でSVGとGeoJSONを作成できます。

保存版と厳密に同じ見た目が必要な場合は、`examples/2026-09-29/`の完成品を利用します。

## 履歴を残す

`examples/2026-09-29/`は初期の完成品です。新しい日付の地図を確定するときは、日付別のフォルダーへ成果物を保存し、対応する変更と出典をローカルGitに記録すると追跡しやすくなります。`dist/`は再生成用の出力先として使用します。

このリポジトリの作図処理は、Xへの投稿や外部サービスへの公開を行いません。公開用の画像を作ることと、外部に投稿することは別の操作です。
