# 更新・点検の手順

生成AIと対話して編集する場合は、[リポジトリの読み込み・対話編集ガイド](AI_WORKFLOW.md)から始めます。このページは作図コードと情報更新の詳細手順です。

## 再作図と情報更新の違い

`./build.sh`は、保存された記述と座標から地図を描き直します。ニュース、AIS、運賃、港湾情報などを検索する機能はありません。情勢・コストの基準日は**2026年9月29日**、共通の航路追記は**2026年10月12日**です。全球図・ホルムズ拡大図には**10月22日の湾岸局所追記**があります。情勢・費用の全面再検証ではありません。

現在の地図として再公開するときは、情報を再確認して地図を編集します。実行日だけを新しい基準日として表示しないでください。基準日を据え置いて再利用する場合は、その時点の整理図であることが伝わるようにしてください。

## 情勢・内容を更新する場合

1. 各地図の出典Markdownを読み、変更の必要がある事項を選びます。紅海・ホルムズの通航、パイプラインの稼働、積替え地点、パナマの制限、費用に関する記述は特に時間に依存します。
2. 運営者、当局、業界機関等の一次資料と信頼できる報道を確認します。記事の公表日、出来事の日付、観測期間を分けて記録してください。匿名情報による報道と公式確認も区別します。
3. `maps/middle-east/build.py`または`maps/global/build.py`で、必要な線・ラベル・注記を編集します。座標は緯度経度の順序を確認し、既存の表現・変換処理に合わせます。
4. 確認した内容に合わせて、同じフォルダーの`metadata.json`の`as_of`を更新します。表題やクレジットを変える場合も同ファイルを編集します。基準日には`YYYY-MM-DD`形式を使います。今回のように一部航路だけを追記する場合は、`as_of`を進めず`route_additions_as_of`に追記日を記録し、画像にも両日を表示します。
5. `docs/middle-east-sources.md`、`docs/middle-east-geometry.md`、`docs/global-sources-and-costs.md`など、対応する根拠と留保を更新します。
6. 対象の地図を再作図し、PNGを目視確認します。異常があれば元のスクリプトを直して再実行します。

地図上の説明は短く保ち、根拠や詳細な留保はMarkdownに記載します。ただし、単独で画像が共有されても重大な誤解につながらない程度の注記は残してください。

全球図第14版では、10月22日の湾岸追記を`local_revision_as_of`、作図更新日を`layout_updated_at`に記録します。画像のヘッダと出力GeoJSONは同じメタデータを参照します。湾岸の保存データは`maps/global/data/gulf-routes.geojson`です。拡大図を更新しても、このファイルには自動反映しません。

## コードの読み方

利用者独自のデータを追加・更新する場合は、まず[生成AIによる追加・更新手順](USER_DATA.md)（[入力仕様](USER_DATA_REFERENCE.md)）を参照してください。`user-data/` または `--data-dir` で指定したフォルダーから、各図に独立したレイヤーを重ねます。既存データは上書きせず、追加項目だけを編集・削除できます。出典・観測日・確認状態は各Featureに記録し、元図とは別の更新日を表示します。

入口は `scripts/build.py` です。各地図の `maps/<地図名>/build.py` を呼び、SVG・GeoJSONを生成した後、`scripts/render.cjs` でPNG化と配置確認を行います。作図にPythonの外部パッケージは使いません。

各地図の作図コードは、設定・座標変換・描画用関数・地図本体・出力の順に並んでいます。図に描く文字や座標は地図本体の節で編集してください。書体・色・線・記号・余白は `design/` のトークンを参照します。[デザインシステム](DESIGN_SYSTEM.md)に編集先と見本帳をまとめています。

| 処理 | 読む場所・役割 |
|---|---|
| 共通の意匠設定 | `design/foundations.json`と`design/profiles/*.json`。`scripts/design_system.py`が読み込む |
| 独自データの形式確認と重ね描画 | `scripts/user_layers.py` の `load_layer()` / `render_layer()`。両図で共用し、表示文字はSVG用にエスケープ |
| 地理座標からSVG座標へ | 両図の `xy()`。入力は `[経度, 緯度]`（度）、出力は画面上のピクセル座標 |
| 中東図の座標変換 | 保存済み背景の `data/base-projection.json` を使う。海路・設備の座標は地図本体で指定 |
| 全球図の曲線 | `smooth()` と `route()`。経度の不連続を解消してから曲線にし、図の端で切る。矢印も同じ曲線の標本点を使う |
| 線・地点・文字 | `line()`、中東図の `point()`・`txt()`、全球図の `dot()`・`text()`。ラベルの位置には地理座標と画面座標を混在させない |
| 全球図のリスク枠 | `risk_bubble()`と「主要リスクを1行ずつ示す説明枠」の節。経路名＋1行のリスク。パナマのみ船型条件を別行に表示 |
| 出典付きの地理情報 | 両図の `features`。中東図の `feat()`、全球図の `route()` 等からGeoJSONへ記録 |

全球図の範囲・投影は、`maps/global/render-base.cjs` の中心・ズーム・画面サイズと、`maps/global/build.py` の座標変換が対応しています。中東図は背景取得時の範囲をJSONから読みます。表示範囲を変える場合は、背景だけでなく投影・ラベルの配置も合わせて見直してください。

`scripts/render.cjs` は実際のブラウザー上の文字枠と、検査用クラスを付けた引出線を確認します。全球図の説明枠内の余白・はみ出しと、全図の文字の画面外へのはみ出しも確認します。すべての地物との接触を検出するわけではありません。問題があってもPNGとQA JSONを残してから終了するため、画像を開いて原因を確認できます。

## 維持する表現

- **中東図：** NGLラインとその凡例は載せません。紅海・ペルシャ湾などの海域ラベルは水平に保ちます。湾内発の紫線はラス・タヌラ付近からホルムズを通過する直航・積替えの共通区間です。紫点線でフジャイラ沖・ソハール沖への積替え接続を示します。個別便の実績・正確な沖合位置として扱いません。バブ・エル・マンデブ海峡等の引出線を文字に重ねないようにします。
- **全球図：** 第16版は6経路・主要地点に、経路名＋1行のリスクを示す小さなバルーンを添えます。費用と細かな荷役注記は省き、詳細資料へ分担します。航路の滑らかな曲線、線上の往復矢印、鮮やかな配色を維持します。パナマのVLCC不可、矢印・破線の意味、作図クレジットは残します。
- **共通：** OSM系のダーク背景、読みやすい日本語、簡潔な注記を維持します。地名の引出線は航路より細い明色の直線とし、暗い細縁で背景から分離します。文字・マーカーの手前で線を止め、`label-leader` クラスで文字との干渉を検査します。文字を地点の左に置く場合は右端、右に置く場合は左端へ線を結びます。真下に置く文字は上辺へ接続します。線との重なりだけでなく、終点と文字の対応・航路からの余白もPNGで確認してください。地図の描画線は模式表現であり、個船の航跡や航海上の推奨経路ではありません。
- **矢印の意味：** 既定の海上ルートは幹線・STS接続とも、1本の線に同色の往復矢印を置きます。船の配船・輸送による往復を模式化するもので、原油の双方向流動、個船の往復完了、往復同一航路の確認を示しません。パイプラインの矢印は原油の送油方向を維持します。費用注記は日本向け調達の評価であり、往復運賃の実額ではありません。独自データの`arrows`は[入力仕様](USER_DATA_REFERENCE.md)に従います。

上記は保存版の意匠方針です。利用者から新たな指定があった場合は、その指示に合わせて更新してください。

ミナ・アル・ハファル沖は港域代表点として扱い、STSと原油SBMを区別します。中東図第10版・全球図第9版では、シディ・ケリル行きだけを示していた灰色の一点鎖線・配船凡例・独立した注記枠を外し、他地域と共通の往復矢印へ統一しました。中東図第11版・全球図第10版では、シディ・ケリルにSBM積載の短い補足を加え、全球図の既存積替え枠をマラッカ沖の日本向けSTSの説明に整理しました。マラッカの根拠は6月の報道で、すべての原油がここを経由する意味にはしません。図は一般的な経路を説明し、船名を挙げた個別事例の注記は載せません。個船の確認範囲は出典資料に残します。この表現変更によって情勢・費用の情報基準日は更新しません。

## 出力の確認

```sh
./build.sh all --check-data
./build.sh middle-east
./build.sh global
```

独自データの検査・描画処理を変更したときは `python3 -m unittest discover -s tests -v` を実行します。空の独自データで元図を再現できることと、`examples/user-data/` のサンプルを両図で描画できることも確認してください。サンプルは実在航路・運航実績を示すものではありません。

`dist/`のPNGを開き、縮小表示と等倍表示の両方で確認します。

- ラベル、注記、引出線、矢印が重なっていないか。
- 航路の曲線が意図せず陸地を横切ったり、海峡・港を飛び越えたりしていないか。
- 全球図の左右端をまたぐ航路が、滑らかに連続しているか。
- 海上ルートの往復矢印が同じ線上に自然に収まり、パイプラインの送油方向と区別されているか。
- 引出線の端が対象航路や地点を指し、不要な矢印頭が付いていないか。
- 注記枠の中で、タイトル・状態・本文の行間と上下余白が自然か。
- 図の基準日、表題、凡例、作図クレジット、背景の帰属表示が適切か。
- 出典Markdownと図の表現が一致しているか。

`*.qa.json`は描画確認の補助です。自動検査だけでは、曲線と海岸の関係や記述の正確性までは判断できません。`--svg-only`ではPNGも描画確認用JSONも更新しないため、公開前は通常のビルドを行ってください。

## デザインとPC表示の点検

書体・文字階層・色・線・記号・余白の方針は[デザインシステム](DESIGN_SYSTEM.md)、実際の設定値は `design/foundations.json` と `design/profiles/*.json` にまとめています。数値をこの文書へ重複して転記せず、JSONを正本として更新します。共通色への参照（`"{colors.loading}"`等）を保ち、中東図の国・海域名の個別サイズ差は `geographic_size_offsets` を編集します。[見本帳](design-system.html)は同じ設定から再生成します。

```sh
python3 scripts/check_design.py
python3 scripts/build_design_guide.py
node scripts/preview.cjs docs/design-system.html docs/design-system.png --selector '#specimen'
./build.sh all
node scripts/preview.cjs dist/middle-east.svg dist/middle-east-pc1440.png
node scripts/preview.cjs dist/global.svg dist/global-pc1440.png
```

文字サイズを変えたら引出線の終点も確認します。通常のPNGとPCを想定した1440px幅の両方で、主要港・通過点・荷役補足の順序、バルーンのまとまり、文字の密集を確認してください。国・大陸・海域は縁なしの明朝体、主要港は細縁の角ゴシック、設備・補足は縁なしの角ゴシックです。水平な海域ラベル、鮮やかな航路色、長方形の注記枠と直線の引出線、プロファイルで指定した本文の行送りを維持します。

フォントは利用環境のものを使い、ファイルは同梱しません。代替書体で字幅が変わるため、OS・フォント・ブラウザーを変更したら再描画します。コントラスト検査と自動配置検査は補助であり、図全体のアクセシビリティや情報の正確性を認証するものではありません。

## 背景を更新する場合

```sh
npm run refresh-basemap -- middle-east
npm run refresh-basemap -- global
./build.sh all
```

この処理だけはネット接続が必要です。背景と投影設定は組み合わせて使用します。画像だけを別サイズ・別範囲の地図に差し替えると、航路と海岸線がずれる原因になります。背景を変更した場合は、両者の整合と帰属表示を確認してください。

背景取得に失敗した場合は、既存背景で通常の再作図ができるか確認します。新しい背景が必要なときだけ、通信環境や配信サービスを確認して再取得します。

## 環境を変える場合

- 初期準備は`npm ci`を使い、保存された依存関係を再現します。
- Google Chromeがなければ、`npx playwright install chromium`の後に`CHROME_CHANNEL=chromium`を指定します。
- ChromeまたはChromiumの実行ファイルを選ぶ場合は`CHROME_PATH`、Pythonを選ぶ場合は`PYTHON`を指定します。
- 日本語が四角になる場合や文字幅が変わる場合は、日本語フォントを確認します。フォントやブラウザーの違いで、改行・字幅・描画が変化する可能性があります。
- Node.jsやブラウザーが使えない環境では、`./build.sh all --svg-only`でSVGとGeoJSONを作成できます。

保存版と厳密に同じ見た目が必要な場合は、対象日の `examples/` 内の完成品を利用します。READMEの掲載版は、中東図が `examples/2026-10-12-design-system/` の第15版、全球図が `examples/2026-10-22-global-risks/` の第16版です。全球図は6経路それぞれに1行のリスクを示します。バルーンなし第15版は `examples/2026-10-22-global-overview/` に保存しています。費用・リスク枠付きの第14版は `examples/2026-10-22-global/` に保存しています。情勢・費用の基準日は9月29日です。

## READMEの掲載図を更新する

1. 通常ビルドのPNGとSVGを確認し、確定した版を `examples/` の保存先へコピーします。掲載PNGが `dist/` の確認済みPNGと一致することを照合してください。
2. READMEの画像埋込み、高解像度PNG、SVG、PC表示例の参照先を同じ保存版へ揃えます。表の版番号も各地図の `metadata.json` に合わせます。
3. 画像・SVGのURL末尾には `?v=版番号-SHA256の先頭12桁` を付けます。ファイル内容の変更に合わせてURLも更新し、古い画像のキャッシュが残る可能性を減らします。ハッシュは `shasum -a 256 ファイルのパス` で確認できます。
4. 公開後、READMEの表示とリンク先を確認します。作図の更新日と情勢・コストの情報基準日は分けて記載します。

## 履歴を残す

`examples/2026-09-29/`は初期の完成品です。新しい日付の地図を確定するときは、日付別のフォルダーへ成果物を保存し、対応する変更と出典をローカルGitに記録すると追跡しやすくなります。`dist/`は再生成用の出力先として使用します。

このリポジトリの作図処理は、Xへの投稿や外部サービスへの公開を行いません。公開用の画像を作ることと、外部に投稿することは別の操作です。

## 英語版の更新

```sh
./build.sh all --lang en
./build.sh gulf-hormuz-oman --lang en
./build.sh all --lang en --data-dir examples/user-data-en --output-dir dist/en/tutorial
python3 -m unittest discover -s tests -v
```

英語は`dist/en/`へ、日本語は`dist/`へ出力します。`--output-dir`指定時は言語フォルダーを自動付加しません。英語の表示内容と文字位置は`maps/<map-id>/locales/en.json`で編集し、地理座標と出典は元データを共有します。組込み文字の未翻訳、言語の伝播、元資料・経路の保持は`tests/test_map_language.py`で検査します。

独自データの名前・注記・出典は自動翻訳しません。ステータス・追加データの日付表示だけを出力言語に揃えます。英語で共有する際は、実際に英語で用意した独自データを指定します。既定の空レイヤーでも、両言語を通常描画して文字・引出線・枠の配置を目視確認します。
